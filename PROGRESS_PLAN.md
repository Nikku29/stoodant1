# Student progress: teacher entry, insights, parent dashboard, WhatsApp reports

Status (2026-10-18): the calculations, the parent dashboard (`/parent`) and the teacher page (`/teacher`) are built with sample data. Nothing is saved and no WhatsApp message is sent yet. Both pages are `noindex`, are not linked from the landing page, and load as their own chunks, so the landing page bundle does not grow (its stylesheet is byte-for-byte the same; the shared route list grows by about 0.7 KB before compression).

The repository has no log-in page yet; the landing page, 404 page and these two previews are the only routes.

## 1. How non-technical teachers enter attendance and marks

The rule: a teacher should never "make data". They tap and type numbers; the system turns that into reports.

The teacher page on their phone has three tabs, one job each:

| Tab | What the teacher does | Why it is easy |
|---|---|---|
| Attendance | Opens today's batch. Everyone is already marked present; taps only the children who missed class, then Save. | A full class is one tap. The usual case (most children present) needs no work. |
| Test marks | Types the test name and "out of", then one number per child. Empty box = missed the test. | Marks above the maximum, or anything that isn't a number, are flagged before Save is allowed. Marks out of 20 and out of 50 are converted to percentages automatically. |
| Notes | Taps one or two ready-made lines per child ("Asks good questions", "Homework pending"…). | No writing. The lines are written by Stoodant in a calm, positive tone, so a report never sounds harsh. Edit them in `src/config/dashboardConfig.ts`. |

Supporting choices:

- **One-time setup by Stoodant, not the teacher**: batches, students, subjects and timetable are entered by the admin. The teacher only sees "today's class".
- **Teacher logs in with their phone number** (Firebase phone OTP), so there is no password to forget.
- **Reminder**: a WhatsApp nudge to the teacher 30 minutes after class if attendance wasn't marked.
- **Mistakes are fixable** for 48 hours by the teacher, then only by an admin, and every change is logged.
- **Later, optional**: import attendance from the Zoom/Meet participant list so the teacher only confirms it.
- **Fallback for the least confident teachers**: they send marks on WhatsApp to the Stoodant number and an admin enters them. The data model stays the same.

## 2. How insights are calculated

Each child is compared only with their own earlier results, never with classmates, and there are no ranks. All rules live in `src/lib/progress/insights.ts` (with tests in `src/test/progress-insights.test.ts`); the thresholds are in `src/config/dashboardConfig.ts`.

| Insight | Formula | Notes |
|---|---|---|
| Attendance % | classes attended ÷ classes held × 100 | "Late" counts as attended. Classes Stoodant cancelled are not counted, so they never lower a child's attendance. |
| Test % | marks ÷ maximum × 100 | Makes a quiz out of 20 and a test out of 50 comparable. A missed test is left out of averages, not counted as zero. |
| Subject average | mean of that subject's test percentages in the period | Week = Monday to Sunday; month = 1st to last day. |
| Overall average | mean of the subject averages | So a subject with many small quizzes doesn't outweigh the others. |
| Improvement | average of the latest 3 tests minus the average of the 3 before them, in percentage points | With fewer tests it uses smaller groups (2 vs 2, 1 vs 1). With fewer than 2 marked tests it says "Too early to tell". |
| Trend label | +5 points or more: "Improving". Within ±5: "Steady". −5 or lower: "Needs a little focus". | Wording is deliberately gentle. |
| Next focus | the subject that dipped most; if none dipped, the lowest subject when it trails the best by 5+ points | The report always says what the teacher will do about it. |
| Doing well in | the highest subject average (when it isn't the focus subject) | |
| Attendance note | below 75% in a month adds an offer to find a better class time | Never a warning. |

## 3. Parent dashboard (`/parent`)

Mobile-first, one column: child's name and batch; a This week / This month switch; three numbers (attendance, average marks, improvement); one plain sentence summary; a card per subject with average, trend and a small line of past test results; class-by-class attendance dots; recent tests; teacher notes; a preview of the exact WhatsApp report; and an "Ask the teacher on WhatsApp" button. It uses sample data until parent logins exist; the page already takes the child's records as input, so wiring it to Firestore doesn't change the page.

## 4. Weekly and monthly reports on WhatsApp

Most parents will only ever see the WhatsApp message, so it carries the full story and the dashboard is optional. The message text is generated by `src/lib/progress/reportText.ts` from the same numbers as the dashboard.

- **Weekly**, Sunday evening: attendance, this week's tests, which subjects moved up or down, teacher's notes, link to the dashboard.
- **Monthly**, on the 1st: attendance, average and change, every subject with its trend, "doing well in", "next focus", teacher's notes, link.

How sending will work (not built yet; needs your decision):

1. Pick a WhatsApp Business API provider. Options: Meta's WhatsApp Cloud API directly (cheapest, more setup), or an Indian provider such as Interakt, AiSensy or Gupshup (dashboard, easier template approval, small monthly fee). Business-initiated messages need **pre-approved templates** (category "utility"); Meta charges per message; a utility message in India was around 12 paise at the last rates I know of, so check the current rate card before choosing.
2. Submit two templates (weekly, monthly) with variables for the child's name, numbers and notes.
3. A scheduled Cloud Function (Sunday 7 pm IST, and the 1st at 10 am IST) builds each child's message and sends it through the provider. Each send is logged in `reports/` so nothing goes twice, and a failed send is retried.
4. Parents opt in to WhatsApp reports during enrolment (consent recorded in `consentLog`), and can reply "STOP".
5. Optional: a monthly PDF or image card of the dashboard attached to the monthly message.

## 5. Data model to add (Firestore, all private)

| Collection | Key fields |
|---|---|
| `batches/{id}` | `name`, `classLevel`, `board`, `subject`, `teacherUid`, `schedule[]`, `studentIds[]` |
| `students/{id}` | `name`, `classLevel`, `board`, `parentUids[]`, `parentPhoneE164`, `whatsappOptIn {at, noticeVersion}`, `batchIds[]` |
| `sessions/{batchId_date}` | `batchId`, `date`, `status` (`held`/`cancelled`), `attendance {studentId: "present" \| "late" \| "absent"}`, `markedBy`, `markedAt` |
| `assessments/{id}` | `batchId`, `subject`, `title`, `date`, `max`, `scores {studentId: number \| null}`, `enteredBy` |
| `notes/{id}` | `studentId`, `batchId`, `subject`, `lines[]`, `teacherUid`, `date` |
| `reports/{studentId_period}` | `kind` (`weekly`/`monthly`), `period`, `text`, `sentAt`, `providerMessageId`, `status` |

Access: teachers read and write only their own batches; parents read only their own child (custom claims `role: teacher | parent`). Students are minors, so verifiable parental consent comes before any of this goes live (see BACKEND_PLAN.md §5).
